# Motion Telemetry Report Specification

This document defines the complete file catalog and data formats generated by `bun scripts/render.ts motion`.

The report package is designed for direct ingestion by autonomous AI coding agents, continuous integration review gates, and human art directors.

---

## 1. CLI Usage & Generation

```bash
bun scripts/render.ts motion --url http://localhost:5173 --only <scene-id|scene-file> \
  --from <start-s> --to <end-s> --out <fresh-out-dir> \
  [--fps 60] [--scale 1] [--samples 1] [--shutter 0] [--bin 0.25] [--topn 12] \
  [--events 4.5,8.0,12.5] [--event-offsets -0.2,-0.1,0,0.05,0.1,0.2,0.4] \
  [--palette ink=#0A0A0B,bone=#EEE9DF,paper=#F7F4EC,signal=#FF4D12,signal-lite=#F9845A] \
  [--allow-blank 0-0.6] [--compare path/to/reference/summary.json]
```

*Note: `--out` must point to a new directory. Telemetry analysis runs on $480 \times 270$ frames ($4 \times 4$ box-downscaled from $1920 \times 1080$).*

---

## 2. Artifact Catalog & File Index

| File | Format | Purpose & Contents |
| :--- | :--- | :--- |
| **`report.md`** | Markdown | Structured markdown report containing executive scorecards, ranked top-5 findings, metric aggregates with physical units, and visual evidence links. |
| **`findings.json`** | JSON | Machine-readable log of all Tier A, B, and C findings with stable content-addressed IDs, time windows $[t_0, t_1]$, severity, and reviewer waivers. |
| **`summary.json`** | JSON | Holistic metric aggregates (mean, p50, p90, max) and timing distributions used for baseline comparisons via `--compare`. |
| **`frames.csv`** | CSV | Per-frame timeseries: $E, E_{p95}, \text{flow}_{dx}, \text{flow}_{dy}$, luma, contrast, edge density, signal%, shimmer, segs, render ms, spp. |
| **`text.csv`** | CSV | Text trace: frame index, timestamp $t$, string content, font family, cap height, bounding box $[x_{\min}, y_{\min}, x_{\max}, y_{\max}]$, opacity, layer ID. |
| **`events.json`** | JSON | Catalogue of detected cuts, musical downbeats, audio kick transients, and animation state triggers. |
| **`timeline.png`** | PNG | 1920px stacked timeseries plot with aligned time axes ($E$, luma, signal%, edge density, text height, frame render ms). |
| **`slitscan.png`** | PNG | Center-column spatiotemporal slit-scan (4px/frame, wrapping at 1920px) showing camera speed ramps and visual rhythm. |
| **`strip_<label>.png`**| PNG | High-resolution event filmstrips sampled at `--event-offsets` around cuts and key animation beats. |
| **`rgbtime_<label>.png`**| PNG | RGB temporal composite ($R = t-2, G = t, B = t+2$) revealing velocity vectors and spatial fringing. |
| **`events/<label>.csv`**| CSV | High-precision per-frame metric table for $\pm 0.5\,\text{s}$ surrounding key diagnostic events. |

## 4. Autonomous Agent Consumption Pattern

When an autonomous agent invokes telemetry to verify a code change:
1. **Check Exit Status**: Verify that `summary.json` reports `"blocking_count": 0`.
2. **If Blocking Flags Exist**:
   - Parse `findings.json` to isolate the rule (`F04`, `F05`, `F10`, or `F16`) and timestamp range $[t_0, t_1]$.
   - Inspect the corresponding `strip_<label>.png` or `rgbtime_<label>.png` artifact to observe the defect visually.
   - Apply geometric or temporal code fix in the scene source file.
   - Re-run `bun scripts/render.ts motion` until blocking count is strictly 0.
3. **If Advisory Flags Exist**:
   - Check if the advisory represents intentional art (e.g. highlight flash or transition burst).
   - If intentional, add a waiver entry to `findings.json`.
